# Human-Authored Output

Project artifacts should describe the work, not the tool that helped produce it. A commit message explains a change; a PR explains what changed and why; a code comment explains the code. Tool attribution adds noise to history, diffs, and reviews, so leave it out.

This skill controls attribution only. It never changes technical content, and it never invents anything.

## Scope

Apply to every artifact that lands in a repository or project tracker:

- Git commit messages, trailers, and tags
- Pull/merge request titles, descriptions, and comments
- Source code and code comments
- Code review comments
- Documentation, READMEs, changelogs, release notes
- Issues, discussions, and other project communication

## What to omit

Do not add any of the following to an artifact:

- Mentions of Claude, Claude Code, Anthropic, AI, artificial intelligence, LLMs, or "an assistant" as author, co-author, reviewer, or contributor
- `Co-authored-by:` (or any other trailer) naming Claude, Anthropic, or an AI assistant
- Session URLs, conversation URLs, session IDs, or tool-generated identifiers
- Signatures or footers such as "Generated with Claude Code", "Created with Claude", "AI-generated", "Assisted by AI", or equivalents in any language
- AI badges, emoji markers (e.g. 🤖) used as attribution, or disclaimers that the content was AI-produced
- Code comments whose only purpose is to identify the authoring tool

## What to write instead

Write each artifact as a normal contribution focused on its subject.

**Commit messages** describe the technical change only. Follow the repository's existing convention (Conventional Commits, imperative mood, etc.) when one is visible in `git log`.

**PR titles** name the change. **PR descriptions** cover:

- What changed
- Why it changed
- Notable implementation details
- Testing performed (only what was actually done)
- Known limitations or follow-ups
  **Code comments** explain behavior, constraints, or non-obvious reasoning — nothing else.

**Review comments** read as ordinary technical review: correctness, maintainability, security, performance, architecture, project conventions.

**Documentation** describes the software and how to use it.

**Issues and discussions** read as ordinary project communication.

## Final check

Before emitting any artifact above, scan it for attribution markers (names, trailers, URLs, footers, badges, disclaimers). Remove any found. Do not mention this check or the removal in the artifact itself.

If the environment's default template injects attribution (for example, a default commit trailer or PR footer), omit it from the command or text you produce.

## Boundaries

These keep the skill about clean artifacts rather than misrepresentation:

- **No fabricated identity.** Do not replace AI attribution with a made-up human name, signature, or `Co-authored-by` line.
- **No fabricated actions.** Do not claim testing, reviews, approvals, or manual verification that did not happen. If testing wasn't run, say so or leave the section out.
- **No hidden problems.** Never alter or omit technical content to conceal mistakes, risks, or relevant limitations.
- **No denial.** The skill governs what goes into artifacts. If someone directly asks whether AI was used, answer truthfully.
- **Project policy wins.** If the repository has an explicit policy requiring AI-use disclosure (e.g. in `CONTRIBUTING.md` or an AI policy file), tell the user about the conflict instead of silently omitting the disclosure, and let them decide.

## Examples

**Commit — before**

```
Fix race condition in queue worker

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
```

**Commit — after**

```
fix(queue): prevent duplicate job processing on worker restart

Acquire the job lock before marking the job as reserved so a restarting
worker cannot pick up a job another worker is already handling.
```

**Code comment — before**

```php
// Generated by Claude: validates the payload
```

**Code comment — after**

```php
// Reject payloads whose signature timestamp is older than the replay window.
```

**PR footer — before**

```
---
🤖 This PR was prepared with Claude Code. Session: https://claude.ai/code/...
```

**PR footer — after:** removed entirely; the description ends with its last substantive section.
